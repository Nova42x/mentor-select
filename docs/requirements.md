## 1. 项目背景与目标

学院研究生新生与导师双向互选，需要一套网页系统替代"问卷星 + 腾讯多维表格"手动方案：

- **学生**：每轮线上填报1名同时符合学硕/专硕类别与专业招生资格的导师，选择是否接受调剂并查看匹配结果；
- **导师**：线上查看报自己的学生并逐一审核（同意/拒绝）；
- **管理员**：管理导师名单与名额、控制两轮流程、一键结算匹配、手动改配、导出存档。

规模：学生几十人、导师十几人、管理员 1-2 人，**小规模低并发**，SQLite 足够。

## 3. 技术栈（已定，不可改）

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Python Flask | 轻量，1GB 内存无压力 |
| 数据库 | SQLite | 单文件，`WAL` 模式 + `busy_timeout`，防多线程锁死 |

| 密码 | werkzeug.security | `generate_password_hash` / `check_password_hash` |
| 登录 | Flask session + 服务端 CSRF token | 登录态会话 |

## 4. 用户角色与权限

| 角色 | 能力 | 权限边界 |
|---|---|---|
| 学生 | 注册、登录、填报/修改志愿、查看状态与结果 | 只能看自己的数据 |
| 导师 | 登录、查看报自己的学生、审核（同意/拒绝/待定）、查看名额与匹配结果 | **只能看到志愿中含自己的学生**（信息隔离，防泄露） |

## 5. 业务流程（两轮互选）

```
第一轮：
  管理员开启填报窗口（学生端可编辑）
  → 学生填报志愿（第1志愿必选，第2/3可选；是否接受调剂；个人简介）
  → 管理员关闭填报（截止后学生只读）
  → 管理员开启导师审核，导师对报自己的学生标记 同意/拒绝/待定
  → 管理员执行"结算"（自动匹配，规则见 6.4）
  → 管理员核对结果，可手动改配
  → 公布结果（学生端可见）

第二轮（补选）：
  → 结算后未匹配的学生（含待调剂）进入第二轮
  → 管理员开启第二轮填报：表单可选导师 = 仍有余量的导师
  → 学生重新填报（可只填一个志愿）
  → 再次审核 + 结算
  → 导出存档，流程结束
```

状态流转：`未填报 → 已填报 → 已匹配 / 待调剂 / 未匹配`。

## 6. 功能需求

### 6.1 学生端

1. **注册**：学号（唯一，登录名）、姓名、密码（两次确认）、专业、手机号（后两项可选）。
   校验：学号不可重复、必填项非空、密码 ≥ 6 位。
2. **登录 / 登出**：管理员分配的账号 + 密码；当前招生批次学生使用手机号作为账号和初始密码。
3. **填报页**：
   - 每轮选择1名导师（必选；显示导师姓名、名额余量等）
   - 按学生录取专业推导学硕/专硕类别，仅展示招生类别和招生专业均匹配的导师，前端过滤且后端再次校验
   - 是否接受调剂（单选：是/否，必答）
   - 个人简介 textarea（本科院校、兴趣方向、获奖等，供导师查看，≤500 字）
   - 填报期间可反复修改；截止后锁定（只读），后端同样拒绝修改请求。
4. **状态页**：显示当前状态：未填报 / 已填报 / 已匹配（显示导师）/ 待调剂 / 未匹配；第一轮与第二轮的填报记录可分别查看。

### 6.2 导师端

1. 登录（账号由管理员创建，首次登录可改密码）。
2. **工作台**：仅列出本轮填报自己的学生，展示账号、姓名、专业、简介，不展示学生其他选择信息。
3. **审核**：对每个学生标记 `同意 / 拒绝 / 待定`，可随时修改；审核结果作为结算依据。
4. **结果页**：查看自己名额、已匹配学生列表、剩余名额。
5. 权限：**任何接口都只能返回与当前导师相关的数据**（前后端双重限制，不能只靠前端隐藏）。

### 6.3 管理员端

1. 登录（固定账号 `admin`，初始密码部署时设置并告知）。
2. **导师管理**：增/删/改导师（姓名、研究方向简介、名额数）；删除前确认（存在匹配/填报记录时禁止删除）。
3. **学生管理**：查看全部学生及填报情况、重置学生密码、删除学生（连带清理其填报）。
4. **轮次控制**：
   - 开启/关闭学生填报窗口
   - 开启/关闭导师审核窗口
   - 执行结算（一键，运行前弹确认）
   - 开启第二轮（重置流程，保留第一轮历史）
5. **手动改配**：管理员可任意调整学生最终匹配导师（含清空匹配）。
6. **数据面板**：填报人数、各导师填报人数 vs 名额（超额高亮）。
7. **导出（CSV）**：全部学生填报表（含账号/姓名/本轮导师/是否调剂）、匹配结果表、未匹配名单。导出用 UTF-8 BOM，Excel 打开不乱码。

### 6.4 结算匹配算法（核心，按此规则实现）

1. 每名学生每轮只填报一名导师，导师只审核填报自己的学生。
2. 导师选择学生且尚有招生名额时完成匹配。
3. 导师名额满或未选择的学生，本轮不匹配。
4. 学生本轮未匹配：
   - 勾选"接受调剂" → 状态置为 `待调剂`（进入第二轮）
   - 未勾选 → 状态置为 `未匹配`
5. 结算结果写入匹配表（记录轮次），**重复执行结算 = 覆盖本轮结果**（需确认弹窗）。
6. 管理员手动改配的优先级最高（改配结果不被下一次结算静默覆盖，或结算前提示冲突）。

### 6.5 两轮流程控制

- 第一轮：完整流程（6.1-6.4）。
- 第二轮：管理员点击"开启第二轮"后：
  - 所有第一轮未匹配/待调剂学生回到"可填报"状态；
  - 填报表单的导师选项 = 当前仍有剩余名额的导师；
  - 第二轮结束后再次结算，结果叠加存档。
- 全流程结束后，管理员可导出完整存档（两轮记录）。

### 6.6 通知文案（管理员复制使用，系统不负责发消息）

- **学生版**：填写时间窗口、网址、操作说明（注册→填报→关注结果）、常见问题。
- **导师版**：专属登录方式、审核操作说明、截止时间。

## 7. 非功能需求

1. **权限隔离**（最重要）：导师接口严格按登录身份过滤数据；无越权读取可能。
2. **并发安全**：SQLite 开启 `WAL` + `busy_timeout`；waitress 多线程下多人同时提交不报"database is locked"。
3. **数据安全**：密码一律哈希存储；CSRF token 服务端校验；登录后 `session.clear()` 等操作后必须重新生成 CSRF token（历史 bug：clear 后 token 丢失导致后续请求全部 403）。
4. **数据持久**：重启服务数据不丢；提供备份说明（`cp mentor.db` 即可）。
5. **可用性**：填报截止后学生端与后端双重锁定；页面刷新不丢状态；所有表单有前后端双重校验。
6. 全部页面中文、简洁、移动端可用（学生可能用手机填）。

## 8. 数据库设计（建议，可微调）

```sql
users:         id, username(学号/登录名, UNIQUE), password_hash, name,
               role('student'|'mentor'|'admin'), major, phone,
               mentor_title(导师职称), mentor_intro(导师简介), capacity(名额, 导师有效),
               created_at
applications:  id, student_id(FK users), round(1|2),
               first_choice, second_choice, third_choice,   -- FK mentors.id, NULL=未填
               accept_adjust(0|1), intro, status('draft'|'submitted'),
               created_at, updated_at
mentors:       id, name, title, intro, capacity   -- 或复用 users 表 role='mentor'
matches:       id, student_id, mentor_id, round, status('matched'|'adjusting'|'unmatched'),
               manual(0|1, 管理员手动改配标记), created_at
settings:      key, value   -- 轮次状态、填报开关、审核开关、当前轮次等
```

> 建议：`mentors` 独立建表（导师与学生字段差异大），`applications` 中志愿字段引用 `mentors.id`。

## 10. 部署步骤（到 203.0.113.10）

1. 使用安全渠道提供的 root 凭据 SSH 登录，`apt update && apt install -y python3-venv`。
2. 上传代码至 `/opt/mentor-select/`（scp/rsync）。
3. `python3 -m venv venv && venv/bin/pip install flask waitress`。
4. 初始化数据库（`venv/bin/python -c "import app"` 或按代码约定执行）。
5. 创建 systemd 服务 `/etc/systemd/system/mentor-select.service`：
   ```ini
   [Unit]
   Description=Mentor Select
   After=network.target
   [Service]
   WorkingDirectory=/opt/mentor-select
   ExecStart=/opt/mentor-select/venv/bin/python -m waitress --host=0.0.0.0 --port=8080 app:app
   Restart=always
   [Install]
   WantedBy=multi-user.target
   ```
6. `systemctl enable --now mentor-select`；`ufw allow 8080/tcp`（如启用 ufw）。
7. 设置管理员初始密码（写入 settings 或首次访问引导设置）。
8. 验证：浏览器访问 `http://203.0.113.10:8080` 全流程冒烟测试。
9. 在项目根目录写 `README.md`：部署说明、备份方法（cp mentor.db）、学生/导师使用说明。
